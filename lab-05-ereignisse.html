Ereignisse im Ablauf Events along the way

Prozesse warten: auf eine Lieferung, eine Antwort, einen Termin. Und sie werden gestört: Eine Anlage fällt aus, eine Frist verstreicht. BPMN hat dafür Zwischenereignisse im Ablauf, angeheftete Ereignisse am Rand einer Aufgabe und ein Gateway, bei dem nicht Daten, sondern die Umwelt entscheidet. Dieses Lab führt sie an einer Ersatzteilbestellung, einer Anlagenstörung und einer Apotheke ein. Processes wait: for a delivery, a reply, an appointment. And they get disturbed: a machine fails, a deadline passes. BPMN has intermediate events in the flow for that, boundary events on the edge of a task and a gateway where not data but the environment decides. This lab introduces them with a spare-part order, a machine failure and a pharmacy.

ZwischenereignisseIntermediate events

Bisher standen Ereignisse nur am Anfang und am Ende. Ein Zwischenereignis liegt im Ablauf: Die Marke hält an, bis etwas eintritt (eintretend, leeres Symbol), oder sie löst im Vorbeigehen etwas aus (auslösend, gefülltes Symbol). Der Doppelkreis unterscheidet es vom Start und vom Ende. So far events stood only at the beginning and the end. An intermediate event lies in the flow: the token stops until something occurs (catching, empty symbol), or it triggers something in passing (throwing, filled symbol). The double circle distinguishes it from start and end.

NachrichtenereignisMessage event eine Nachricht empfangen oder sendenreceive or send a message
  • Eintretend (leer)Catching (empty)Die Marke wartet, bis die Nachricht eintrifft: Auftragsbestätigung, Lieferung, Antwort des Kunden.The token waits until the message arrives: order confirmation, delivery, customer's reply.
  • Auslösend (gefüllt)Throwing (filled)Die Marke sendet eine Nachricht und läuft sofort weiter: Kunden informieren, Bestellung absenden.The token sends a message and continues at once: inform customer, send order.
  • Als StartAs startEin Nachrichten-Startereignis sagt: Dieser Prozess wird von außen ausgelöst.A message start event says: this process is triggered from outside.

Stolperfalle:Pitfall: Warten ohne Ausweg: Trifft die Nachricht nie ein, bleibt die Instanz für immer stehen. Ein Timer daneben (ereignisbasiertes Gateway) oder am Rand der Aufgabe schafft den Ausweg. Waiting without a way out: if the message never arrives, the instance stays stuck forever. A timer next to it (event-based gateway) or on the boundary of the task creates the way out.

ZeitereignisTimer event eine Dauer, ein Zeitpunkt, ein Rhythmusa duration, a point in time, a schedule
  • Im AblaufIn the flowDie Marke wartet: „Wöchentliche Freigaberunde“, „Nach 5 Minuten“. Das ist eine Wartestelle und erzeugt Liegezeit.The token waits: “weekly approval round”, “after 5 minutes”. That is a waiting point and creates idle time.
  • Am RandOn the boundaryEine Frist für die Aufgabe: „Nach 2 Tagen ohne Antwort“.A deadline for the task: “after 2 days without reply”.
  • Als StartAs startEin Rhythmus: „Täglich 8:00 Uhr“ startet jeden Tag eine neue Instanz.A schedule: “daily 8:00” starts a new instance every day.

Stolperfalle:Pitfall: Ein Timer wartet immer die volle Zeit ab. „Spätestens nach drei Tagen, sonst früher“ ist kein Timer, sondern ein ereignisbasiertes Gateway mit Timer und Nachricht. A timer always waits the full time. “At the latest after three days, otherwise earlier” is not a timer but an event-based gateway with timer and message.

Angeheftete EreignisseBoundary events

Manches kann während einer Aufgabe passieren: Die Anlage fällt aus, eine Frist verstreicht, der Kunde storniert. Solche Ereignisse hängt man an den Rand der Aufgabe. Die Marke sitzt in der Aufgabe; tritt das Randereignis ein, entsteht ein Ausnahmepfad. Some things can happen during a task: the machine fails, a deadline passes, the customer cancels. Such events are attached to the boundary of the task. The token sits in the task; if the boundary event occurs, an exception path arises.

Angeheftetes EreignisBoundary event was während einer Aufgabe eintreten kannwhat can occur during a task
  • UnterbrechendInterruptingDurchgezogener Rand. Die Aufgabe wird abgebrochen, die Marke verlässt sie über den Ausnahmepfad. Der normale Ausgang entfällt.Solid border. The task is cancelled, the token leaves it via the exception path. The normal exit is dropped.
  • Nicht unterbrechendNon-interruptingGestrichelter Rand. Die Aufgabe läuft weiter, eine zweite Marke startet den Nebenpfad. Typisch: Erinnerung, Eskalation.Dashed border. The task keeps running, a second token starts the side path. Typical: reminder, escalation.
  • ArtenKindsFehler (Blitz, immer unterbrechend), Zeit (Uhr), Nachricht (Umschlag), Eskalation, Signal.Error (lightning, always interrupting), timer (clock), message (envelope), escalation, signal.

Stolperfalle:Pitfall: Der Nebenpfad eines nicht unterbrechenden Ereignisses darf nicht in die Aufgabe zurückführen: Sie läuft ja noch, und die zweite Marke würde sie ein zweites Mal betreten. Regel R10. The side path of a non-interrupting event must not lead back into the task: it is still running, and the second token would enter it a second time. Rule R10.

Das Fehlerereignis ist immer unterbrechend: Ein Fehler beendet die Aufgabe. Die Apotheke zeigt den anderen Fall, einen nicht unterbrechenden Timer, der das Warten nicht beendet, sondern eine Nachfrage daneben stellt. The error event is always interrupting: an error ends the task. The pharmacy shows the other case, a non-interrupting timer that does not end the waiting but places an enquiry next to it.

Das ereignisbasierte GatewayThe event-based gateway

Nach der Bestellung kann zweierlei passieren: Die Bestätigung kommt, oder drei Tage vergehen. Welcher Fall eintritt, weiß niemand vorher; es hängt von der Umwelt ab, nicht von Daten. Dafür gibt es das ereignisbasierte Gateway: Der Prozess wartet, und das erste Ereignis, das eintritt, wählt den Pfad. Die anderen Ereignisse werden verworfen. After the order two things can happen: the confirmation comes, or three days pass. Which case occurs nobody knows in advance; it depends on the environment, not on data. For that there is the event-based gateway: the process waits, and the first event to occur chooses the path. The other events are discarded.

Ereignisbasiertes GatewayEvent-based gateway das erste Ereignis wählt den Wegthe first event chooses the way
  • BedeutungMeaningExklusiv wie das XOR, aber die Entscheidung trifft die Umwelt: Nachricht oder Frist, Antwort A oder Antwort B.Exclusive like XOR, but the environment decides: message or deadline, reply A or reply B.
  • DanachAfterwardsAusschließlich eintretende Zwischenereignisse (oder Empfangsaufgaben). Keine Aufgaben, keine Bedingungen an den Pfaden.Only catching intermediate events (or receive tasks). No tasks, no conditions on the paths.
  • ZusammenführungMergeMit einem gewöhnlichen XOR-Gateway.With an ordinary XOR gateway.

Stolperfalle:Pitfall: Eine Aufgabe direkt hinter dem ereignisbasierten Gateway ist der häufigste Fehler damit; der Prüfer meldet ihn als R09. A task directly after the event-based gateway is the most frequent error with it; the checker reports it as R09.

Lesetechnik.Reading technique. „Sobald“, „wenn … eintrifft“ verraten ein eintretendes Nachrichtenereignis; „nach x Tagen“, „spätestens“ einen Timer; „kann während … passieren“, „falls … ausfällt“ ein Randereignis; „entweder … oder … zuerst“ ein ereignisbasiertes Gateway.“As soon as”, “when … arrives” reveal a catching message event; “after x days”, “at the latest” a timer; “can happen during …”, “if … fails” a boundary event; “either … or … first” an event-based gateway.

ÜbungenExercises

Sechs Übungen. In der Simulation lassen sich Randereignisse und Ereignisse hinter dem ereignisbasierten Gateway per Klick auslösen: So sehen Sie, was unterbrechend und nicht unterbrechend mit den Marken macht.Six exercises. In the simulation, boundary events and events after the event-based gateway can be triggered by click: that is how you see what interrupting and non-interrupting do to the tokens.

ZusammenfassungSummary

  • Zwischenereignisse warten (leer, eintretend) oder senden (gefüllt, auslösend).Intermediate events wait (empty, catching) or send (filled, throwing).
  • Angeheftete Ereignisse beschreiben, was während einer Aufgabe passieren kann; unterbrechend beendet sie, nicht unterbrechend erzeugt eine zweite Marke.Boundary events describe what can happen during a task; interrupting ends it, non-interrupting creates a second token.
  • Das Fehlerereignis ist immer unterbrechend und braucht einen Ausnahmepfad mit eigenem Ende.The error event is always interrupting and needs an exception path with its own end.
  • Das ereignisbasierte Gateway lässt die Umwelt entscheiden; danach stehen nur Ereignisse.The event-based gateway lets the environment decide; only events follow it.
