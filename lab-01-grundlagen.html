Warum Prozessmodelle? Why process models?

Bevor das erste Rechteck gezeichnet wird, lohnt ein Blick darauf, was ein Prozessmodell überhaupt leisten soll: Es beschreibt, in welcher Reihenfolge Dinge geschehen, was sie auslöst und womit sie enden, und zwar so, dass Fachabteilung, IT und ein Werkzeug dieselbe Zeichnung lesen. Dieses Lab führt die drei Begriffe ein, auf denen alles Weitere aufbaut, stellt die Werkzeuge vor und zeigt, wie eine .bpmn-Datei in Adonis CE hinein- und wieder herauskommt. Before the first rectangle is drawn, it is worth looking at what a process model is supposed to achieve: it describes in which order things happen, what triggers them and what they end with, in a way that the business, IT and a tool read the same drawing. This lab introduces the three terms everything else builds on, presents the tools and shows how a .bpmn file gets into Adonis CE and out again.

Was ein Prozess istWhat a process is

Ein Prozess ist eine Folge von Tätigkeiten, die durch ein Ereignis ausgelöst wird, ein Ergebnis für einen Kunden erzeugt und dabei Ressourcen verbraucht. Die Aufbauorganisation sagt, wer zu wem gehört; die Ablauforganisation sagt, was in welcher Reihenfolge geschieht. Ein Prozessmodell zeigt die zweite Sicht. Die erste erscheint darin höchstens als Zuständigkeit, in BPMN als Bahn. A process is a sequence of activities that is triggered by an event, produces a result for a customer and consumes resources along the way. The organisational structure says who belongs to whom; the process organisation says what happens in which order. A process model shows the second view. The first appears in it at most as a responsibility, in BPMN as a lane.

Die vier Fragen, die jedes Modell beantwortetThe four questions every model answers

  • Wodurch beginnt es? Ein Ereignis: Eine Bestellung geht ein, ein Patient trifft ein, ein Timer läuft ab.What starts it? An event: an order comes in, a patient arrives, a timer expires.
  • Was geschieht, und in welcher Reihenfolge? Aufgaben, verbunden durch Sequenzflüsse.What happens, and in which order? Activities, connected by sequence flows.
  • Wo verzweigt es? Gateways mit Bedingungen.Where does it branch? Gateways with conditions.
  • Womit endet es? Ein oder mehrere Endereignisse, jedes ein Ergebnis.What does it end with? One or more end events, each a result.

Das kleinste vollständige Modell hat also ein Startereignis, mindestens eine Aufgabe und ein Endereignis. Hier ist eines. Klicken Sie auf die Symbole. The smallest complete model therefore has a start event, at least one task and an end event. Here is one. Click the symbols.

Modell, Instanz, MarkeModel, instance, token

Das Modell oben beschreibt den Kiosk-Ablauf ein einziges Mal. Jede tatsächliche Bestellung ist eine Prozessinstanz: ein Durchlauf mit eigenem Anfang, eigenem Ende und eigenen Daten. Vierzig Bestellungen am Vormittag sind vierzig Instanzen desselben Modells. Der Bauplan ist einer, die Häuser sind viele. The model above describes the kiosk flow exactly once. Every actual order is a process instance: one run with its own start, its own end and its own data. Forty orders in a morning are forty instances of the same model. There is one blueprint, there are many houses.

Um zu verstehen, was ein Modell tut, denkt man sich eine Marke (englisch Token), die beim Startereignis geboren wird, über die Sequenzflüsse wandert, an jeder Aufgabe wartet, bis sie erledigt ist, und beim Endereignis verschwindet. Gateways sind Weichen für Marken: Das exklusive lässt eine durch, das parallele vervielfältigt sie, die parallele Zusammenführung wartet, bis alle da sind. Jedes Lab dieser Umgebung hat den Knopf „Marke laufen lassen“, mit dem Sie das ausprobieren. To understand what a model does, imagine a token that is born at the start event, travels along the sequence flows, waits at every task until it is done and disappears at the end event. Gateways are switches for tokens: the exclusive one lets one through, the parallel one multiplies it, the parallel join waits until all have arrived. Every lab in this environment has the button “Run a token” to try that out.

Warum das zählt.Why it matters. Fast jeder Fehler in einem Prozessmodell wird sichtbar, wenn man eine Marke hindurchschickt: die Verzweigung ohne Bedingung, die Zusammenführung, die ewig wartet, die Aufgabe, in die zwei Marken laufen. Deshalb steht die Marke am Anfang und nicht am Ende dieses Kurses. Almost every error in a process model becomes visible when you send a token through it: the split without a condition, the join that waits forever, the task two tokens run into. That is why the token comes at the beginning of this course, not at the end.

Wozu BPMN?Why BPMN?

Prozesse lassen sich mit Kästchen und Pfeilen in jedem Zeichenprogramm skizzieren. Sobald aber zwei Personen dieselbe Skizze verschieden lesen, braucht es eine Vereinbarung, was ein Kästchen bedeutet. BPMN (Business Process Model and Notation) ist diese Vereinbarung: ein Standard der OMG, seit 2011 in Version 2.0, der festlegt, welche Symbole es gibt, wie Marken durch sie laufen und wie ein Modell als XML-Datei gespeichert wird. Die Notation ist für drei Leser zugleich gemacht: Processes can be sketched with boxes and arrows in any drawing program. But as soon as two people read the same sketch differently, an agreement is needed on what a box means. BPMN (Business Process Model and Notation) is that agreement: an OMG standard, version 2.0 since 2011, that defines which symbols exist, how tokens run through them and how a model is stored as an XML file. The notation is made for three readers at once:

  • Die Fachabteilung liest Aufgaben, Ereignisse und Gateways wie einen Comic: von links nach rechts, ohne Schulung.The business reads tasks, events and gateways like a comic: left to right, without training.
  • Die IT findet in denselben Symbolen die technischen Details, etwa welche Nachricht ein Ereignis auslöst.IT finds the technical details in the same symbols, such as which message triggers an event.
  • Das Werkzeug kann das Modell prüfen, simulieren und in einer Prozess-Engine ausführen, weil die Bedeutung jedes Symbols festgelegt ist.The tool can check, simulate and execute the model in a process engine, because the meaning of every symbol is defined.

Die Vorlesung ordnet BPMN im Camunda-Framework nach Freund und Rücker ein: strategisches Modell (grob, für Entscheidungen), operatives Modell (was diese Umgebung übt) und technisches Modell (ausführbar). Alle drei benutzen dieselben Symbole in unterschiedlicher Tiefe. The lecture places BPMN in the Camunda framework by Freund and Rücker: strategic model (coarse, for decisions), operational model (what this environment practises) and technical model (executable). All three use the same symbols at different depth.

Eigenheiten beim Import.Quirks of the import. Adonis benennt Elementtypen in seiner eigenen Sprache („Aufgabe“ mit Untertyp statt „Send Task“), zeigt manche Datenobjekte und Anmerkungen anders und verlangt für die Simulation die Ansicht „Standard mit Simulation“ statt „Kompakt“. Die Bedeutung des Modells ändert sich dadurch nicht. Was fehlt oder anders aussieht, lässt sich in Adonis nachziehen; die Datei bleibt die gemeinsame Grundlage. Adonis names element types in its own language (“task” with a subtype instead of “send task”), shows some data objects and annotations differently and requires the view “Standard with simulation” instead of “Compact” for the simulation. The meaning of the model does not change. Whatever is missing or looks different can be adjusted in Adonis; the file remains the common basis.

Die .bpmn-DateiThe .bpmn file

Eine .bpmn-Datei ist XML und besteht aus zwei Teilen. Der erste beschreibt den Prozess: welche Aufgaben, Ereignisse und Gateways es gibt und welche Sequenzflüsse sie verbinden. Der zweite, das Diagram Interchange (DI), beschreibt die Zeichnung: wo jedes Symbol liegt und über welche Wegpunkte jede Linie läuft. Deshalb kann ein Werkzeug ein importiertes Modell neu anordnen, ohne seine Bedeutung zu ändern, und deshalb ist ein Bild kein Modell. A .bpmn file is XML and consists of two parts. The first describes the process: which tasks, events and gateways exist and which sequence flows connect them. The second, the diagram interchange (DI), describes the drawing: where every symbol lies and through which waypoints every line runs. That is why a tool can rearrange an imported model without changing its meaning, and why a picture is not a model. 

<bpmn:definitions xmlns:bpmn="http://www.omg.org/spec/BPMN/20100524/MODEL" …>
  <bpmn:process id="Process_uc01" name="Kaffee am Kiosk zubereiten">
    <bpmn:startEvent id="s1" name="Kaffee bestellt">
      <bpmn:outgoing>Flow_s1_t1</bpmn:outgoing>
    </bpmn:startEvent>
    <bpmn:task id="t1" name="Bohnen mahlen"> … </bpmn:task>
    <bpmn:sequenceFlow id="Flow_s1_t1" sourceRef="s1" targetRef="t1" />
    …
  </bpmn:process>
  <bpmndi:BPMNDiagram>
    <bpmndi:BPMNPlane bpmnElement="Process_uc01">
      <bpmndi:BPMNShape bpmnElement="t1">
        <dc:Bounds x="290" y="65" width="120" height="80" />
      </bpmndi:BPMNShape>
      …
</bpmn:definitions>

Sie müssen dieses XML nie schreiben. Lesen können sollten Sie es, denn in Lab 10 erzeugt eine KI genau solche Dateien, und die Frage, ob sie stimmen, entscheidet sich im Modell, nicht im Bild. You never have to write this XML. You should be able to read it, because in lab 10 an AI produces exactly such files, and whether they are right is decided in the model, not in the picture.

ZusammenfassungSummary

  • Ein Prozessmodell zeigt die Ablauforganisation: Auslöser, Reihenfolge, Verzweigungen, Ergebnis.A process model shows the process organisation: trigger, order, branches, result.

  • BPMN 2.0 legt Symbole, Markenverhalten und Dateiformat fest, damit Fachbereich, IT und Werkzeug dasselbe lesen.BPMN 2.0 defines symbols, token behaviour and file format so that business, IT and tool read the same thing.
